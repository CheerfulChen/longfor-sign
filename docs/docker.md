# Docker 管理面板

Docker 版自带常驻调度器。服务器与容器保持运行后，每天自动生成新计划，无需配置 cron 或华为云触发器。

## 启动

```bash
git clone https://github.com/CheerfulChen/longfor-sign.git
cd longfor-sign
cp .env.example .env.server
```

编辑 `.env.server`：设置 `ADMIN_USERNAME` 和至少 12 位的 `ADMIN_PASSWORD`。样例密码会被程序拒绝。然后执行：

```bash
docker compose up -d --build
docker compose ps
docker compose logs --tail=100 app
```

浏览器打开 `http://127.0.0.1:8088`。远程服务器通过 SSH 隧道访问：

```bash
ssh -L 8088:127.0.0.1:8088 用户名@服务器地址
```

默认端口仅绑定服务器本机。需要多人远程访问时，配置 HTTPS 反向代理，再将 `.env.server` 的 `COOKIE_SECURE` 改为 `true` 并重建容器。不要通过明文公网传输账号凭据。

此版本从源码构建，没有已发布的镜像地址。需要 Docker Engine 与 Compose 插件。

## 添加账号

在「账号管理」添加名称、登录 token 和该账号的小程序 DXRisk token。开启 APP 签到时，还需分别填写该账号的 **APP 登录 token** 与 **APP DXRisk token**；不能默认沿用小程序登录 token。APP 使用独立的 `L00602 / L0 / Source=2` 请求头与 APP User-Agent。每个账号分别配置。面板提供「小程序 User-Agent」与「APP User-Agent」，可分别粘贴对应客户端请求头；留空表示保留已保存的值，未配置时使用该入口的默认 UA。配置的 UA 也会用于该入口的日历查询、验证请求，以及小程序的 token 续期。UA 不是完整设备指纹，不能替代对应的 DXRisk token。编辑时凭据留空表示保留旧值，页面不会回显原始凭据。

小程序登录 token 会在执行前尝试续期并保存。APP 登录 token 当前独立保存、手动更新，尚未验证 APP 专用续期链路。DXRisk token 不自动续期。会话被服务端撤销、设备风控失效或要求人机验证时，需要在官方客户端处理，再更新面板凭据。

### 自动验证与手动凭据

Docker 版已接入原脚本的图像识别、背景还原、轨迹和 AC 编码流程。小程序或 APP 签到返回 `8040012` / `8040016` 且日历确认仍未签时，自动尝试一次受支持的滑块验证。验证通过后再查一次日历，仍未签才带验证凭据重试签到，并再次查询日历核实结果。结果不确定、验证失败或类型不支持时停止，不无限重试。

APP 和小程序均将验证接口返回的完整 token 原样写入 Captcha 请求头，不无条件追加 `:challenge`。重试保留各自登录 token、风控值、UA、渠道和 Source。验证码 token 不替换登录 token，也不被当成新的 DXRisk token。

复用了已有识别算法与偏移设置，接入和重试逻辑经过模拟测试；未用真实账号验证新版本通过率，不能保证所有验证码都能自动通过。

APP Captcha token 仍可手动填写已完成验证后的完整请求头值，不要填写 `undefined`。此值只供下一次任务使用，任务领取时从数据库清除；不会长期保存自动生成的验证码凭据。若已失效，会在受支持的错误响应下触发上述自动验证。

旧数据库会自动增加独立 APP 登录凭据和两套 UA 字段，保留已有账号、计划与密钥。旧账号未补充 APP 登录 token 时，小程序继续运行，APP 不会使用小程序凭据代发请求，会记录需要补充配置。

## 每日随机计划

在「计划与推送」配置：

| 设置 | 行为 |
| --- | --- |
| 全天随机 | 每天在所选时区的 00:00～23:50 内安排任务，预留跨日余量 |
| 指定时间段 | 例如 08:30～22:15；只在此范围内安排和启动自动签到 |
| 账号最小间隔 | 默认 15 分钟，可调整；从前一个账号实际执行结束后计算 |
| 时区 | 默认北京时间 Asia/Shanghai，可选择伦敦或 UTC |
| 自动运行 | 关闭后暂停自动签到；手动队列仍可执行 |

时间每天重新随机，账号顺序也随机。计划保存到 SQLite，容器重启后保留；不会每次刷新页面都重新抽签。后台约每 5 秒检查一次，计划精确到秒，实际执行会受检查周期、网络和前一个任务耗时影响。

指定时段目前限同一天，例如 22:00～次日 06:00 不支持。保存设置或修改账号会重新安排未执行的任务；已结束的账号当天不会重跑。若剩余时间无法容纳账号数量与最小间隔，保存会提示调整范围；今天时段已经结束则从明天开始。

每个账号串行完成小程序和可选 APP 签到，两个入口之间等待 20 秒。上一个任务耗时较长时，后续任务顺延；错过时间段的任务记录为「错过」，不会在时段外补跑。服务器关机跨过整个时段，也不会补签过去日期。

「立即执行」会加入今天的队列，允许在自动时段外执行，但仍遵守账号间隔。当天已有结束记录时不会重复执行；结果不确定时请先检查官方客户端签到日历。

## 结果与推送

总览显示今日时间线与下次计划，「执行记录」保留执行结果。调用前查询签到日历，签到后复核；已签到则跳过。

在「计划与推送」填入 Bark Device Key，保存后可点击测试推送。每个账号结束后发送结果，当日全部结束后发送汇总。推送失败会逐步延长间隔后重试，重试只发送通知，不重新签到。响应丢失或服务异常退出时，通知可能重复。

没有配置 Bark 时仍可通过面板查看结果。受支持的滑块验证会自动尝试一次，失败后需在客户端人工处理。

## 持久化、备份与恢复

Compose 命名卷 `longfor_data` 挂载到 `/data`，包含 SQLite 数据库、加密密钥 `.key` 和调度状态。凭据加密存储；密钥与数据库都在同一数据卷，备份应整体保存并限制访问。丢失密钥无法解密原凭据。

停止服务后复制一致的备份，再启动：

```bash
docker compose stop app
mkdir -p backups
docker compose cp app:/data ./backups/data
docker compose start app
```

每次备份请使用新的目录，避免覆盖旧备份。备份目录含敏感数据，不要提交 Git 或上传 Release。

恢复时先停止容器，将备份目录内容整体复制回 `/data`，包括隐藏的 `.key`。例如在已创建容器且卷为空时：

```bash
docker compose stop app
docker compose cp ./backups/data/. app:/data/
# 必要时恢复数据卷属主（容器使用 UID/GID 10001）
docker compose run --rm --user 0 --entrypoint chown app -R 10001:10001 /data
docker compose up -d
```

不要使用 `docker compose down -v`，它会删除数据卷。不要只恢复数据库而遗漏 `.key`。更改管理员密码后，重新创建容器会使旧登录会话失效。

## 升级与运行约束

升级前备份，再更新源码并重新构建：

```bash
git pull
docker compose up -d --build
docker compose logs --tail=100 app
```

当前设计为单容器、单 Gunicorn worker；后台文件锁阻止多个调度进程同时使用同一数据目录。不要自行增加 workers 或扩容多个副本。强制退出时正在执行的任务会记为「结果待确认」，不会自动重放，避免重复请求。

容器以非 root 用户运行，根文件系统只读，健康检查访问 `/healthz`。调度进程在等待时不向龙湖接口轮询，仅到期执行任务。Docker 本身不收取本程序运行费用，服务器资源和网络由所用服务器承担。
