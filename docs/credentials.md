# 登录、风控与验证码凭据

| 名称 | 用途 | 更新方式 |
| --- | --- | --- |
| 小程序登录 token | 小程序账号会话，写入 token / X-LF-UserToken | 执行前尝试自动续期并保存 |
| APP 登录 token | APP 账号会话 | 独立配置，当前手动更新 |
| DXRisk token | 客户端风控标识 | 每个账号、每个入口分别配置，不自动续期 |
| Captcha token | 验证通过后供本次签到使用的凭据 | 自动处理受支持验证后取得，或在 Docker 中手动提供完整值 |
| User-Agent | 客户端环境声明 | 两端分别设置；可选，有各自默认值 |

同一客户端的 token 与 X-LF-UserToken 使用同一个登录值。不同账号必须使用各自的登录和风控值；UA 可以相同，它不是手机唯一设备指纹。

小程序和 APP 的活动编号、渠道、风控来源及默认 UA 分开处理。所有部署方式调用同一份核心，配置方式见 [公共配置](configuration.md)。

## 登录续期

小程序采用 token2key → key2token 流程，取得新值后先持久化，再发送业务请求。续期失败时不会虚构有效期；原会话是否有效由服务端决定。重新登录后手动更新配置，会按稳定账号标识重新绑定凭据。

续期不会替换 APP 登录 token、DXRisk token 或 Captcha token，也不保证客户端不会主动登出。各入口的持久化差异见公共配置文档。

## 验证与结果

签到前查日历，已签到则跳过。发送后复查，只有确认已签才记成功。受支持的风控响应且日历仍未签时，尝试一次原有滑块处理流程，验证后再查日历，仍未签才重新提交。

验证接口返回的完整 token 原样写入 X-LF-DXRisk-Captcha-Token，无论小程序还是 APP 都不会无条件追加 :challenge。返回值中已经存在的后缀保留。undefined 不视为有效凭据。

自动验证失败、类型不支持或结果无法确认时，查看官方客户端并人工处理。本项目的控制流程通过模拟测试，真实通过率仍取决于服务端和当前图片。

根目录早期 JS 和图像分析文件继续保留作研究记录；生产入口使用 core/ 中的同一套适配。
